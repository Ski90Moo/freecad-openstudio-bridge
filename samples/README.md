# The worked example

Everything the docs quote numbers from. A two-storey light-industrial building
of 36 spaces (plus an attic story the roof carves out on its own) drawn on a
0° north axis — the same model in the banner image.

| File | What it is |
|---|---|
| `FloorplanTest-05.FCStd` | **The drawing.** The input to the whole pipeline: two traced story sketches, the scale-calibrated plan images, four elevation images, a parapet shading sketch, the roof extents, and the window and door outlines. Fully tagged, so it runs as shipped — including one wall carrying a real `OS_AirBoundaryOverride=SOLID` (fire-rated) tag. |
| `plan.json` | Written by `fc_export_floorplan.py` from that drawing — the exact vertices, and **the seam between the two halves** of the bridge |
| `surfaces.json` | Written by `dump_osm_geometry.py` from the model built off that plan |
| `openings.json` | Written by `fc_export_openings.py` from the same drawing |

The three JSON files are regenerated by every round trip — they are here so the
exchange format can be read without owning FreeCAD or OpenStudio. `schema/`
holds the formal schemas; these are what they look like filled in.

There is no `rated-walls.txt`/`--solid-surface` file here: the fire-rated wall
declares itself, tagged directly on its own sketch edge in the FCStd, and
`fc_export_floorplan.py` resolves that into `plan.json` at export time. A
surface-name file was the older, positional mechanism — it rotted silently on
any rebuild that renumbered surfaces, which is exactly what the tag survives.

See the [Quickstart](../README.md#quickstart) for the four commands that
reproduce them.

`plan.json` earns its place twice over. Everything upstream of it needs
FreeCAD; everything downstream needs only the `openstudio` wheel. Committing it
is what lets CI build the whole model on Ubuntu, Windows and macOS without
FreeCAD anywhere in sight — the model side is exercised end to end on every
push, not just its parts. Its `exported_utc` stamp changes on every re-export,
so expect that one line to differ even when nothing else has.

## The drawing

Self-contained: the plan and elevation images are stored *inside* the FCStd,
not referenced from disk, so the document opens correctly wherever it is
cloned. Nothing in it points anywhere on the machine it was drawn on.

It is the full working document rather than a trimmed-down input — the built
OpenStudio geometry has been imported back into it, which is why it carries
359 `Part::Feature` surfaces alongside the 9 sketches. That is the state the
fenestration workflow needs anyway: `--into` puts the generated surfaces in
the document the plan was traced in, because a sketch can only attach to
geometry in its *own* document.

Room names are generic — `102 | Office`, `403 | Warehouse`, `501 | Mechanical
Room` — and no drawing set, title block or client information travels with it.

## What is in the JSON

`surfaces.json` — the model as built (spaces, surfaces, subsurfaces and
shading may be one build ahead of `build_osm_geometry.py`'s own bare-geometry
output, per the ordinal note in the Quickstart). Each surface carries its
name, OpenStudio handle, space, story, thermal zone, surface type, boundary
condition, construction, gross and net area, azimuth, tilt, outward normal,
and its full vertex loop in metres.

`openings.json` — the windows and doors, each with its host surface, host
space, subsurface type and vertices.

Two things worth noticing, because both are load-bearing elsewhere:

- **Handles are present but are not identity.** They are regenerated on every
  rebuild, which is the whole reason [IDENTITY.md](../IDENTITY.md) exists.
- **`construction` is mostly `null`.** Geometry is all the bridge claims to
  produce; constructions, weather and HVAC are assigned downstream. The one
  exception here is the 32 surfaces across the drawing's 6 air-boundary
  constructions (`is_air_boundary: true`) — `find_air_boundaries.py` derives
  and sizes those from the plan itself, including the one the fire-rated
  wall's tag excludes, so they are already assigned in this file.
